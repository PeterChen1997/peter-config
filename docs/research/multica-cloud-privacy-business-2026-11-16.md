### 安全结论和适用边界

- **日志脱敏有方向差异。** v0.9.0 的 daemon 对工具参数在发送前调用 `redact.InputMap`。常规 `tool_result` 路径在客户端会规范化并截取至 8 KiB，输出和文本类记录的模式脱敏发生在服务端接收后。这个大小只限定该路由的工具预览，独立的最终输出和文件上传另有路径。模式过滤可以遮住部分可识别密钥，仍可保留源码、业务文本、路径及未知格式的秘密。 [预览预算](https://github.com/multica-ai/multica/blob/8cd8a2db978d532d8627c78cd29f05deab6c6f17/server/internal/daemon/tool_output_preview.go#L9-L32) · [客户端事件](https://github.com/multica-ai/multica/blob/8cd8a2db978d532d8627c78cd29f05deab6c6f17/server/internal/daemon/daemon.go#L10249-L10340) · [服务端过滤](https://github.com/multica-ai/multica/blob/8cd8a2db978d532d8627c78cd29f05deab6c6f17/server/internal/handler/daemon.go#L5865-L5876) · [模式过滤实现](https://github.com/multica-ai/multica/blob/ff41e7a77010fcac63f9d1e7244161fe99b6b69e/server/pkg/redact/redact.go#L152-L168)
- **服务端在信任边界内。** TLS 保护传输，任务所属范围、工作区权限、运行令牌和签名下载限制正常访问。观察到的任务消息路径由服务端读取可解析内容、脱敏、入库和推送，没有用户独占密钥的端到端加密。短期运行令牌绑定用户、工作区、Agent 与 run，最长 24 小时。源码无法证明生产人员访问审批、备份权限、日志副本或所有租户隔离始终按设计运行。v0.9.0 发布说明列过私有项目经运行、引用和自动化等路径的可见性修复，也说明服务版本会影响实际隔离。 [任务消息访问与事件](https://github.com/multica-ai/multica/blob/8cd8a2db978d532d8627c78cd29f05deab6c6f17/server/internal/handler/daemon.go#L5791-L5830) · [运行令牌](https://github.com/multica-ai/multica/blob/8cd8a2db978d532d8627c78cd29f05deab6c6f17/apps/docs/content/docs/auth-tokens.mdx#L78-L84) · [v0.9.0 发布说明](https://github.com/multica-ai/multica/releases/tag/v0.9.0)
- **权限应按 daemon 的 Unix 用户评估。** v0.9.0 的 Linux Codex 默认使用 `danger-full-access`，Antigravity 的无人值守适配器默认跳过工具权限确认。独立工作目录和运行记录隔离方便协作。操作系统身份、文件权限、VM 边界和网络隔离决定运行能接触什么。若 daemon 用户持有个人 SSH/Git 凭证或能访问 Docker daemon，风险扩到这些资源。Docker 官方将标准 Docker 组视为 root 级权限。Private Runtime 控制其他成员绑定/运行的能力，云端仍可处理同一 Runtime 回报。 [官方安全模型](https://github.com/multica-ai/multica/blob/8cd8a2db978d532d8627c78cd29f05deab6c6f17/apps/docs/content/docs/security-model.mdx#L8-L46) · [Linux Codex 策略](https://github.com/multica-ai/multica/blob/8cd8a2db978d532d8627c78cd29f05deab6c6f17/server/internal/daemon/execenv/codex_sandbox.go#L64-L113) · [Antigravity 参数](https://github.com/multica-ai/multica/blob/8cd8a2db978d532d8627c78cd29f05deab6c6f17/server/pkg/agent/antigravity.go#L852-L877) · [Docker 组权限](https://docs.docker.com/engine/install/linux-postinstall/#manage-docker-as-a-non-root-user)
- **政策承诺与生产留存。** 2026-10-22 的政策说 Multica 不出售个人信息、不使用内容训练模型。AWS/Vercel 等可以在美国及其他国家处理数据，PostHog 在登录态收到姓名和邮箱，崩溃日志仍可能含出错细节。公开前端禁用 PostHog 会话录屏与常规自动采集，保留异常上报。工作区存在期间保留内容，删除后恢复备份可能继续保留一段时间，政策没有给出固定天数。删除已删工作区的上传对象需联系支持。未从查阅的公开资料核实生产 SOC 2 报告、后台人工访问细则、固定数据驻留或删除 SLA。 [隐私政策](https://multica.ai/privacy) · [PostHog 配置](https://github.com/multica-ai/multica/blob/ff41e7a77010fcac63f9d1e7244161fe99b6b69e/packages/core/analytics/index.ts#L118-L161)

连接官方 Cloud 时，v0.9.0 daemon 默认启用自动更新（可由环境变量或 CLI 关闭），自托管默认关闭。静态审阅适用于固定的版本和配置。将更新纳入部署管理，可以持续核对服务端和 Runtime 的信任范围。 [更新默认值](https://github.com/multica-ai/multica/blob/8cd8a2db978d532d8627c78cd29f05deab6c6f17/server/internal/daemon/config.go#L618-L630)

## 如何选择

低敏任务可以把 Multica Cloud 当作带执行记录的协作 SaaS 试用。涉及客户数据、生产资源或私有代码时，分别确认组织允许的数据出境范围、模型账号条款和 daemon 能访问的凭证。优先用专用 VM 或普通 Unix 用户、限定仓库和权限的凭证、不挂载生产 Docker socket。Cloud Agent 配置不宜填生产密钥。隔离和自托管解决的是不同问题，应同时评估。 [运行安全模型](https://github.com/multica-ai/multica/blob/8cd8a2db978d532d8627c78cd29f05deab6c6f17/apps/docs/content/docs/security-model.mdx#L8-L46) · [Agent 凭证说明](https://github.com/multica-ai/multica/blob/ff41e7a77010fcac63f9d1e7244161fe99b6b69e/apps/docs/content/docs/agents-create.mdx#L127-L149)

需要自行控制任务历史和附件时，可以把 Web、API、PostgreSQL 和附件存储部署在可控网络。默认自托管服务仍向 Multica 每日发送随机持久部署 ID、版本和汇总使用量。服务端设置 `DO_NOT_TRACK=1` 可同时禁用该遥测的采集和发送。PostHog 使用独立的 `ANALYTICS_DISABLED` 开关。仍使用远程 Codex/Google 模型时，推理数据继续由各自供应商处理。对联网要求严格的部署，还需分别检查更新通道、存储、外部集成及自托管可选的 LLM 配置。已有 Cloud 历史不会因改连接端点自动转移或删除。 [自托管指南](https://github.com/multica-ai/multica/blob/ff41e7a77010fcac63f9d1e7244161fe99b6b69e/SELF_HOSTING.md#L5-L23) · [自托管 LLM 配置](https://github.com/multica-ai/multica/blob/ff41e7a77010fcac63f9d1e7244161fe99b6b69e/SELF_HOSTING_AI.md) · [隐私政策](https://multica.ai/privacy)
